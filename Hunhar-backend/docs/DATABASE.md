# THEUNOiA Database Design (PostgreSQL 16)

## Principles

* **Database per service.** 11 databases (`<service>_db`), each owned by its own login role (`<service>_user`). A service can't read another service's tables; it uses that service's API or events. Cross-database references are plain `UUID` columns without foreign keys.
* **Schema as code.** Flyway migrations (`<service>/src/main/resources/db/migration`) plus the shared platform migration (`common-lib/src/main/resources/db/common/V0_1__platform_tables.sql`). Hibernate never changes the schema (`ddl-auto: none`).
* **Keys and types.** `UUID` primary keys (safe to expose, generated by the app), `TIMESTAMPTZ` in UTC, `NUMERIC(14,2)` for money, `VARCHAR` with `CHECK` constraints for enums, `JSONB` for flexible structures, generated `TSVECTOR` columns with GIN indexes for search.
* **Integrity in the database.** `CHECK` constraints (non-negative balances, valid ranges, state machines), unique and partial-unique indexes for business invariants, append-only ledgers enforced by triggers, and derived counters maintained by PL/pgSQL triggers.
* **Concurrency.** Optimistic locking (`version` columns) for aggregates, pessimistic `SELECT … FOR UPDATE` for wallets and escrow, conditional atomic updates (`balance + n >= 0`) for credits, and `FOR UPDATE SKIP LOCKED` for multi-replica workers (outbox relay, reminder scheduler).
* **Reliable events.** Every database contains `outbox_events` (transactional outbox) and `processed_events` (consumer idempotency).

## Platform tables (every database)

| Table | Purpose |
|---|---|
| `outbox_events` | events written in the business transaction, published by the relay (partial index on unpublished rows) |
| `processed_events` | ids of consumed events: exactly-once effects under at-least-once delivery |
| `schema_migrations` / `flyway_schema_history` | migration history |
