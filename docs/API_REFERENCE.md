# Hunhar API Reference

Every REST endpoint the backend exposes, the frontend function that calls it, what you send, and what comes back. Generated by `python docs/gen_api_doc.py` from the controller, DTO and entity source code (`Hunhar-backend/*/src/main/java`) and `Hunhar-frontend/src/services/api.ts`, so field names and rules match the code.

_126 endpoints._

## Conventions

**Base URL.** The frontend calls the API gateway only: `VITE_API_BASE_URL` (default `http://localhost:8080`). The gateway routes `/api/v1/**` to the four services below. `/internal/**` service-to-service endpoints are never exposed through the gateway and are not listed here.

**Authentication.** Log in with `POST /api/v1/auth/login` and send the returned token on every call:

```http
Authorization: Bearer <token>
```

The gateway validates the JWT and passes the user id and role to the services. A missing or expired token returns `401`; `api.ts` then clears the session and redirects to `/login`. Roles are `FREELANCER`, `CLIENT` and `ADMIN`.

**Response envelope.** Every JSON response has this shape; the documented "Response `data`" is what sits in `data`:

```json
{ "success": true, "message": "Operation successful", "data": { }, "timestamp": "2026-11-01T10:30:00Z" }
```

**Errors** use the same envelope with `success: false`, no `data`, and a human-readable `message` the UI shows as-is:

| Status | When |
|---|---|
| 400 | Validation failed (the first field error is the message) or a business rule was broken, e.g. "Not enough credits" |
| 401 | No/invalid/expired token, or wrong login credentials |
| 403 | Signed in but not allowed (wrong role or not the owner) |
| 404 | Resource or route not found |
| 405 | Wrong HTTP method |
| 409 | Someone else changed the record at the same time; reload and retry |
| 413 | Upload larger than the limit |
| 500 | Unexpected error; the message carries a reference id that appears in the service log |
| 503 | A downstream service is unavailable |

**Types.** Ids are UUID strings. Money is in INR as a decimal number. Dates are ISO-8601 (`yyyy-MM-dd` for dates, `yyyy-MM-ddTHH:mm:ss` for timestamps). A "page of X" response is a Spring page: `{ content: X[], totalElements, totalPages, number, size }`.

## Key flows

1. **Sign up (email OTP).**
   1. `POST /api/v1/auth/otp/send {email}`
   2. `POST /api/v1/auth/otp/verify {email, otp}`
   3. `POST /api/v1/auth/register/client` or `/register/freelancer`, then `POST /api/v1/auth/login`.
2. **Hire.**
   1. The client posts with `POST /api/v1/projects` (`publish: false` saves a draft; publish later with `POST /api/v1/projects/{id}/publish`).
   2. The freelancer bids with `POST /api/v1/bids/project/{projectId}`, which spends credits.
   3. The client shortlists or declines, then awards with `POST /api/v1/bids/{bidId}/award`. The project becomes ACTIVE and a chat opens.
3. **Escrow payment.**
   1. The client tops up the wallet: `POST /api/v1/payments/orders {purpose: WALLET_TOPUP, amount}`, then Razorpay checkout, then `POST /api/v1/payments/orders/{id}/verify`.
   2. The client funds a milestone: `POST /api/v1/workspace/milestones/{id}/fund` moves the money into escrow.
   3. The freelancer submits: `POST /api/v1/workspace/milestones/{id}/deliverables`.
   4. The client approves: `POST /api/v1/workspace/deliverables/{id}/review?approve=true`.
   5. The client releases: `POST /api/v1/workspace/milestones/{id}/release`. The freelancer is paid minus the platform commission and an invoice is generated.
   6. Payouts: `POST /api/v1/wallets/payout` (minimum amount and KYC rules come from the platform settings); an admin processes them.
4. **KYC.**
   1. The freelancer submits with `POST /api/v1/kyc/aadhaar`.
   2. An admin lists pending requests with `GET /api/v1/kyc/admin?status=PENDING_REVIEW`.
   3. The admin decides with `POST /api/v1/kyc/{userId}/approve?approved=true|false&reason=`.
5. **Disputes.**
   1. The client or the hired freelancer raises one with `POST /api/v1/disputes/project/{projectId}`.
   2. An admin resolves it with `POST /api/v1/disputes/{id}/resolve {status: RESOLVED|DISMISSED, resolutionNotes}`.
